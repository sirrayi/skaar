# Plan P1: own game module skeleton

Goal: replace the stock baseq3 game modules with our own C++20 modules, loaded natively.
The client boots to our main menu, and "Test room" (or `dev.sh`) drops the player into `testroom` with working movement.
No Quake 3 assets are referenced anywhere.

## Architecture
```
game/
  shared/   C++ shared by the modules: Q3 header bridge, 2D draw kit (fonts, rects, theme)
  sgame/    server game  -> base/qagame.dylib  (entities, spawn, clients, pmove on the server)
  cgame/    client game  -> base/cgame.dylib   (snapshots, prediction, view, HUD)
  ui/       menus        -> base/ui.dylib      (main menu, in-game menu, loading screen)
```
- The module ABI stays ioq3's: `extern "C"` `dllEntry` + `vmMain`, with syscall numbers from `g_public.h` / `cg_public.h` / `ui_public.h`.
  Each `vmMain` catches C++ exceptions and turns them into `Com_Error`, so nothing unwinds into the engine.
- Movement reuses the GPL Q3 code as-is for now: `code/game/bg_pmove.c`, `bg_slidemove.c`, `bg_misc.c` are compiled (as C) into both sgame and cgame.
  Server and prediction then run identical code. P5 turns this into the ruleset layer (vq3 vs cpm).
- The cgame snapshot handling and prediction are ports of Q3's `cg_snapshot.c` / `cg_predict.c`, simplified (GPL, we're GPL).
- Upstream `code/game`, `code/cgame`, `code/q3_ui` stay in the tree as reference (P6 ports weapon code from them) but aren't built (`BUILD_BASEQ3_MODULES=OFF`).

## Simulation defaults (feel)
- `pmove_fixed 1`, `pmove_msec 8`: movement runs in fixed 125 Hz steps on both server and client.
- `sv_fps 125`, `snaps 125`, `rate 100000`: the local server ticks at 125 Hz, so entity state is fresh (matters for P3 targets).
- `cg_fov` is the horizontal FOV of the actual window (default 103). FOV conversions come in P2.

## UI theme (VØLUND stage + a trace of Q3)
- Ground: off-black `#0b0b0c` with a faint 64 px grid (the Q3 nod: blueprint/arena floor). Hairline rules at 8% cream. No shadows, square corners.
- Text: cream `#ebe6db`; secondary at 62%. Montserrat 200/300 for titles and items (uppercase, tracked), JetBrains Mono for metadata and numbering.
- One accent: ember `#f2622e`, a muted version of the Q3 menu orange. It marks the selected item and the logo glow, and nothing else.
- Items are numbered (`01 TEST ROOM`). The active item gets an ember tick and full cream; the rest sit at 62%.
- The Skaar mark sits as the "object" on the right of the main menu.
- Console and HUD text: JetBrains Mono atlas (replaces the Fira Code placeholder).

## Done when
- The default build ships only our modules; `./scripts/smoke.sh` passes.
- The client starts at the Skaar main menu. Test room loads the map, you can walk, jump, noclip, and Esc opens the in-game menu.
- No missing-asset warnings at startup.
