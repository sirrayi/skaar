# Plan P0: build baseline

Goal: ioq3 fork builds natively on macOS arm64 (OpenGL2 renderer, SDL2), launches standalone
on our own placeholder assets, and is renamed to Skaar with all GPL headers kept.

## Steps
1. Clone ioq3 with the upstream remote named `upstream`. Our work lives on `main`; upstream merges come from `upstream/main`.
2. Stock baseline build with CMake + Ninja to prove the toolchain works.
3. Identity: `cmake/identity.cmake` (binary names, bundle id, base dir) and the `STANDALONE` block in `code/qcommon/q_shared.h` (window title, home dir, config prefix).
4. Defaults: `BUILD_STANDALONE=ON` (no pak0 check, no id CD key), `BUILD_GAME_QVMS=OFF` and native modules by default (`vm_* 0`), Team Arena off.
5. Placeholder assets in `data/base/`, generated by `tools/gen_placeholder_assets.py`; a CMake target symlinks them into the build tree.
6. Docs: `build-macos.md`, `ioq3-layout.md`, `assets.md`, `macos-notes.md`.

## Done when
- `cmake --build build-fast` is green on arm64.
- `skaarded` boots to its console; the `skaar` client opens a window, loads the native ui module, and quits cleanly with no fatal errors.

## Out of scope
- Replacing q3_ui/cgame/game (P1). The stock menu draws garbage without Q3 art; that's expected.
- App icon: waiting for the Skaar logo file (`misc/skaar/logo.png`).
